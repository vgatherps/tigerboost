The permutation has no signed-shift or indexing defect in the accepted compilation range. For `p` pairs, each lane is the signed `p`-bit integer whose bits are that lane's comparisons, with the last comparison as its sign bit. Each lane ranges from `-2^(p-1)` through `2^(p-1)-1`. Both `raw_of` and the emitted code calculate `raw = lane0 + 2^p * lane1`. Therefore `bias = 2^(p-1) * (1 + 2^p)`, and `bias + raw` is a bijection onto `0..2^(2p)`. This directly explains the block size and bounds; it does not rely on the permutation test calling itself. `sli` keeps the previous low bits and inserts the shifted mask; the generic `shl`/`and`/`or` in `src/jit.rs:616–628` does the same. The LLVM shifts have no `nsw` or `nuw` flags. A negative first operand is legal; the shift count must remain below the integer width. [LLVM 21 shift semantics](https://releases.llvm.org/21.1.0/docs/LangRef.html#shl-instruction).

For odd depths, the extra comparison uses threshold `+inf` and a previously loaded real value (`src/sort_policy.rs:118–122`, `src/jit.rs:455–467,566–577`). It remains false even after `AsTrue` NaN replacement. Only original leaf patterns are reachable; padded permutation entries are never selected. AVX2 does not use this permutation: `movmskpd` supplies lane 0 as the low bit, groups are zero-extended, shifted by their original starting level, and ORed (`src/jit.rs:488–509`). The false padding bit prevents an index beyond the original leaf array. New Rosetta probes test the original bit order through depth 8; all three inspection files' entire 7,000-entry constant blocks were checked against the original workload by `probes/count_assembly.py` using the signed-digit formula above.

The pointer and size checks also hold, with one important distinction between accepted models and accepted compilations:

- `Trees::new` limits each feature span and each individual leaf array to `isize::MAX` bytes (`src/parsed_tree.rs:116–143`). On this 64-bit host it rejects depth 60 before shifting/indexing, while depth 59 still requires its actual `2^59` leaves. Existing validation tests exercise the rejection order without allocating huge arrays.
- The emitter checks padded block lengths, total entry additions, `u32` array length, and total byte length before creating LLVM arrays or permuting leaves (`src/jit.rs:195–225`). A valid depth-31 model with `2^31` leaves is an exact example rejected by default compilation: odd-depth padding alone needs `2^32` entries. The AVX2 path keeps the original block. Huge models were checked by arithmetic and control-flow inspection, not by allocating tens of GiB.
- Consequently a successfully emitted two-lane tree has at most 30 padded levels (`p <= 15`). The private `raw_of` assertion allowing 16 pairs cannot expose the `1u32 << 32` failure in `permuted_leaves`: the earlier array-length check rejects that model first. All actual shifts and signed intermediates fit `i64`.
- `add nuw` is used for AVX2's nonnegative index plus leaf base, and for zero plus a constant-tree base (`src/jit.rs:505–509,676–681`). Each result is less than the checked total entry count. The signed permutation path uses ordinary `add`, not `add nuw` (`src/jit.rs:650–658`). Its final slot is `leaf_base + slot_within_block`, also within the array. Larger accepted source models return an error before these instructions are emitted.
- On this 64-bit host, the byte-limit error after the `u32` check is unreachable: at most `(2^32-1)*8` bytes already fit `isize`. It remains a useful independent check for a 32-bit host. The `u32` limit itself is stricter than model validation and is reachable in principle.
- `constants` advertises exactly `entry_count*8` dereferenceable bytes. `chunk_base` advertises precisely the suffix after its first threshold slot (`src/jit.rs:303–315`). Constant-only chunks select slot zero; the empty model allocates one entry. Neither attribute extends beyond the allocation. The two pointers may alias safely here because the function only reads the allocation; LLVM's argument `noalias` restriction concerns locations modified during the call. [LLVM 21 parameter attributes](https://releases.llvm.org/21.1.0/docs/LangRef.html#parameter-attributes).
- Every scalar/vector load claims only eight-byte alignment (`src/jit.rs:448–452,558–563,668–669,760–761`). The global itself is aligned to 64. ARM64 uses ordinary unaligned-capable loads; SSE2 uses `movupd` for thresholds and packed feature loads; AVX2 uses memory compares and unaligned-capable feature forms. The SSE2 `movdqa` loads address separately emitted 16-byte-aligned mask constants, not eight-byte-aligned feature rows. Guard-page execution found no row overread in the adversarial fixtures.

The Rosetta gate computes its expected values independently. `reference_scores` calls `Trees::predict` (`examples/x86_check.rs:134–137`), and `write_outputs` exports those values even though it also performs a native-JIT check. `tools/x86_check.c:188–202` visits every exported row and compares eight bytes with `memcmp`; it exits on the first mismatch. `read_exact` rejects short or trailing data.
